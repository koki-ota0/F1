## 0. エグゼクティブサマリ

**PITWALL（ピットウォール）** は、F1ファンのためのオールインワン・ハブです。
ピットウォール（チームの作戦本部）に立つ感覚のまま、**ライブタイミング・順位・カレンダー・ドライバー/チーム情報・ニュース**に加え、**予測・レースシミュレーター・クイズ・ファン登録（推し活）**までを1サイトで提供します。

- **言語**: 日英バイリンガル（切替対応、デフォルト日本語）
- **対象**: 長年ファン / 新規ファン / チームファン / ドライバーファン / ゲーム好き
- **設計思想**: 「情報は早く、遊びは深く、推しとはずっと」

## 3. データ設計

### 3.1 データソース

| 種別 | ソース | 用途 | 認証 |
|---|---|---|---|
| ライブ | **OpenF1 API**（api.openf1.org） | セッション、ポジション、ラップ、間隔、天気、ドライバー | 不要・CORS対応 |
| 歴代/現シーズン | **Jolpica F1 API**（api.jolpica.org, Ergast後継） | レース、順位、ドライバー、コンストラクター | 不要・CORS対応 |
| ニュース | 公式/メディアRSS（F1.com, Autosport, Crash.net他） | ニュースタイトル/リンク | 不要 |
| オフライン | **バンドルJSON**（`server/data/*.json`） | 2025カレンダー、2025グリッド、歴代チャンピオン、クイズ、サーキット | — |

### 3.2 フォールバック戦略（重要）

サンドボックス/オフライン環境でも**サイトが完全に使える**ことを最優先します。

```
[クライアント]
  ├─ ① ブラウザから直接ライブAPIへ（CORSがあれば成功＝真のLIVE）
  ├─ ② 自前サーバ /api/* （サーバから取得＋30秒キャッシュ）
  └─ ③ バンドルJSONを返す（source: "offline"）
UIは source に応じて「LIVE / CACHE / OFFLINE」バッジを表示。
```

- ライブ系は失敗時もセッション情報・カウントダウンは**バンドル＋現在時刻から計算**して表示
- バンドルの統計値は「2024年シーズン終了時」など**基準日を明記**（虚偽にならない）

### 3.3 バンドルデータ内容

- `teams.json` … 10チーム（2025）: 正式名、ベース、発足年、タイトル数、カラー、PU
- `drivers.json` … 20ドライバー（2025グリッド）: 番号、国籍、Debut、戦績（暫定）、PITWALL独自レート、バイオ（日英）
- `calendar.json` … 2025全24戦: 開催日、サーキット情報（距離/周回/コーナー数/ラップレコード/DRSゾーン）
- `champions.json` … 歴代チャンピオン 2010-2024
- `records.json` … オールタイム記録（2024年终了時）
- `trivia.json` … 40問（カテゴリ: history/driver/team/circuit/rule、日英併記）
- `news.json` … オフライン記事（過去の注目ニュース、日付明記）

## 5. ゲーム設計

### 5.1 予測（Predict）
- 対象: 次のレース。**P1 / P2 / P3 / ファステストラップ**を登録
- 採点: P1=10 / P2=7 / P3=5 / FL=5（完全一致）。ボーナス: 3人全員入賞= +5
- 結果がライブで取れない環境では、**シミュレーター結果を「公式結果」として採点**できる（ローカル対戦モード）
- ランキング: ローカル（シードAI名付き）。v2で共有リーグ

### 5.2 レースシミュレーター（Sim）
- ドライバーの**独自レート＋チームレート**にポアソン的ランダム性を乗せ、周回ごとのポジション変動を計算
- 単戦: プログレスバー＋順位のリアルタイム更新アニメ
- シーズン: 24戦を一括計算しファイナル順位表（ドライバー/コンストラクター）

### 5.3 クイズ（Quiz）
- カテゴリ5種 × 出題からランダム5問/ラウンド
- 正解+10XP、連続正解ボーナス、ベストストリーク保存、レベル表示

## 9. AI予測設計（PITWALL APEX）

「高性能なAI予測」を、**説明可能で再現性のある統計モデル**と**任意の外部LLM**の2層で設計しました。

### 9.1 APEX モデル（`src/lib/model.js` / `server/ai.js`）
- **入力**: ドライバーレーティング・チーム戦力（`TEAM_STRENGTH`）・直近フォーム・コース適性prior
- **ベースペース** = 0.55×driverRating + 0.45×teamStrength
- **コース適性**: driverId×circuit の決定的ハッシュで ±2.2pt（再現性ある揺らぎ）
- **分散**: 基礎 σ = 1.7 + (98−base)×0.11（上位ほどブレ小、下位ほどブレ大）＋ **チーム共通ノイズ**（同じチームは好坏を共にする）
- **モンテカルロ 1,500回**: 各試行でDNF・ギャップを採番 → 勝率/表彰台率/TOP10率/期待ポイント/期待順位/FL確率の分布
- **出力**: 確率分布、おすすめP1-P3/FL、確信度、4件のインサイト（日本語／英語）
- **特徴**: オフラインで即実行可（クライアント側）、同一入力なら同一形状が再現、シミュレーターと同一思想で整合

### 9.2 LLM連携レイヤ（オプション）
- `PITWALL_LLM_URL` + `PITWALL_LLM_KEY`（OpenAI互換）を設定すると、`/api/ai-prediction` が **APEX＋LLMのブレンド**を返す
- プロンプトはstrict JSONスキーマ指定。**失敗・不正応答時は自動でAPEXにフォールバック**し、source フィールドで明示
- 応用: 結果が出ない環境でも「AI予測」は死なない（APEX常時可用）

### 9.3 UI
- 予測ページ上部に「AI予測を実行」→ 勝率バーチャート（チーム色）／おすすめカード／インサイト
- 「この予測を採用」で投稿フォームへ自動入力

## 12. 静的ホスティング（GitHub Pages）対応

- **バンドルデータのクライアント同梱**: `scripts/sync-bundle.mjs` が `server/data` → `src/lib/static` にコピーし、`/api` が無い環境でも主要コンテンツを表示（`useApi` が失敗時に自動フォールバック）
- **SPAディープリンク**: `postbuild` が `dist/404.html` を生成（GitHub Pages は未知パスに 404.html を配信）
- **パス対応**: `vite.base = VITE_BASE || './'`。Pagesビルドは `VITE_BASE=/F1/`、Router basename も自動追従
- **API焼き込み**: `dist/api/*.json` を生成し、静的ホストでも基本的なGETはサーバ不要で応答
- **退化の許容範囲**: ファンSNS共有・予測リーダーボード等・動的API依存機能はローカル動作に退化（AI予測・クイズ・シミュレーターは完全動作）

### 11.1 データの誠実性ポリシー
- バンドル（2025シーズン）は「アーカイブ」と明記して表示
- 外部の未検証データ（匿名レポ等）は採用しない。最新化は **Jolpica/OpenF1 からの取得** または **snapshot 更新** のみ
- 統計値には基準日（2024年终了時など）を表記

## 13. v2: AIフォーム学習（AI Form Learning）

- **目的**: 予測を「出す」だけでなく、**結果で自律的に学ぶ**モデルへ。PITWALL APEX は固定評価から、実績で補正される適応モデルに進化する。
- **アルゴリズム**: `src/lib/learning.js`。採点時に各ドライバーの「予想順位 − 実際の順位」を *surprise* として算出し、ドライバーごとのバイアス `bias[d] ← 0.85·bias + 0.15·surprise`（±5クランプ、指数平滑）で保持する。FL はトップ10入り/圏外で別尺度加点。
- **適用**: `predictRace(drivers, teams, race, { bias })` がシミュレーションの基本スコアに `bias` を加算。勝ちすぎる/壊滅的ドライバーの確率が次回から自動調整される。
- **保存**: `localStorage['pitwall.learning']`（静的ホストでも動作）。パネルにサンプル数・的中率・平均誤差・バイアス上位5人を表示し、リセット可能。
- **誠実性**: 「AI」はローカル適応モデルであることを明記。実績が無い限り素のAPEX。

## 14. v2: ファンSNSの返信・フォロー

- **返信（スレッド）**: 投稿ごとに返信スレッド。`GET/POST /api/posts/:id/replies`（最大280字、400/404バリデーション）。UIは開閉式スレッド＋Enter送信。
- **ローカル動作**: 静的ホストではサーバAPIが無いため投稿フィードは空となり、返信も `post.replies` のローカル表示に退化（クラッシュしない）。
- **将来のフォロー**: `follow` のフォロー済みフィードは v2.1 で実装予定（現状は全投稿フィード＋タグフィルタ）。

## 16. 手動ライブ更新（GitHub Pages / 静的ホスト）

- **方針**: 静的ホストには Express が無いため、ブラウザが公共F1 APIを直接叩く。**常時ポーリングはせず**、ナビの「🔄 最新に更新」ボタン押下時にカレンダー＋両順位を一括取得する（ユーザー要件）。
- **モジュール**: `src/lib/live.js`
  - `refreshLive(year)` → calendar / standings.drivers / standings.constructors の3タスクを並列実行し、成功分を `localStorage['pitwall.live.<kind>.<year>']` にキャッシュ、実施結果を `pitwall.live.status` に保存
  - 各タスクは timeout 8s・失敗はそのタスクだけ不合格（部分成功を許容）
- **配線**: `src/components/RefreshProvider.jsx` が `busy / status / message / refresh` を提供し、成功時に `pitwall:live-refreshed` イベントを発火。Calendar / Standings / Home はこれを購読して再取得。
- **表示**: ナビのバッジが `LIVE ✓ 3/3`（全成功）/ `LIVE n/3`（部分）/ `オフライン（キャッシュ/バンドル表示）`。Home の鮮度行は「最終更新 = サーバ最終同期 or 手動リフレッシュ時刻」。
- **読み取り経路**（`src/lib/api.js`）: サーバ `/api/*` → ブラウザ直接 Jolpica → **手動キャッシュ** → クライアント同梱2026データ → offline。つまりオフラインでも直近の更新結果が残る。
- **バックグラウンド定期取得**: サーバがある環境のみ（`meta.mode !== 'static-host'`）5分間隔。静的ホストでは手動のみ。
- **ビルド時オーバーライド**: `VITE_F1_BASE`（Jolpica系）、`VITE_OPENF1_BASE`（OpenF1）でプロキシ/ミラーに向きられる（検閲環境対応）。
